# references/3d.md

A **scenery** is the 3D set a video films. A **3D model** (`3d-model` on the command line) is an object put in sceneries, and never an AI model. Each is a module; one a person should see is listed in `allyhub.yaml`, the rest are code a video or a scenery imports.

## Ready-made

Start here before building a room or an object.

- `allyhub add search --type scenery` lists the sceneries. Adding one brings its baked light.
- `allyhub add search --type 3d-model` lists the models, each at a real product's published size, with its presets, sizes and finishes as parameters.
- `allyhub add search "office desk" --type @polyhaven` finds CC0 models, HDRIs and textures.
- `allyhub add scenery/<name>`, `allyhub add 3d-model/<name>` or `allyhub add @polyhaven/<id>` copies one into the project, which owns it.

A scenery lands in `sceneries/`, the code it shares in `components/`. Its README, in `components/settings/<setting>/`, names its screens, its cameras and the brightness to give a screen.

## A product's interface on a screen

Each scenery names its screens (`monitor-screen`, `laptop-screen`), and a video puts its own interface on one. Not every scenery has every screen, so check its README.

The SDK's `scenery.md` covers screens and the cameras below. `allyhub help 3d` prints where it is.

## Cameras

A ready-made scenery comes with its cameras placed, so pick one before placing your own. Its README lists each one with what it frames in a vertical 9:16 frame.

- **Named cameras and screen shots**, by what they film, a move per part of the screen and angle. Each setting's README lists its own. A demo is filmed from close: a 3D room seen from afar looks fake.
- A camera can frame one element of the interface, such as a button or a field, by its own rectangle; a phone's camera can be held in a hand; a video can cut between cameras. The SDK's `scenery.md` says how.

To see them, `allyhub scenery <item>` lists a scenery's cameras and moves, `allyhub scenery view` draws from them, and `allyhub scenery see` says what each one sees.

## See and measure

| To see                                                         | Run                                   |
| -------------------------------------------------------------- | ------------------------------------- |
| Objects with places and sizes, lights, cameras, moves and bake | `allyhub scenery <item>`              |
| The view from cameras at moments                               | `allyhub scenery view`                |
| The plan and elevations, with every object's name              | `allyhub scenery map`                 |
| What each camera sees: shares of the frame, what hides what    | `allyhub scenery see`                 |
| Surfaces, contacts, gaps and what rests on what                | `allyhub scenery measure`             |
| How a camera moves                                             | `allyhub scenery motion`              |
| Whether a scenery is baked                                     | `allyhub inspect --kind scenery-bake` |
| A screen drawn in the world against its own elements           | `allyhub inspect fidelity`            |

`allyhub help 3d` lists them all.

## Building your own

| To                                                            | Commands                | SDK docs                    |
| ------------------------------------------------------------- | ----------------------- | --------------------------- |
| Build a scenery and its cameras                               | `allyhub help 3d`       | `scenery.md`                |
| Model an object in code, with a subset of Blender's modelling | `allyhub help modeling` | `modeling.md`, `scenery.md` |

A scenery you change is drawn unbaked until `allyhub scenery bake` bakes it again.
